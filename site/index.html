Questions people ask before writing an event loop.

Do I write my own event loop?+

No. VeloceApp::run owns the ingestion thread, the Tokio runtime, the priority drain, and the 60 FPS flush. You implement View and declare routes.

How do background tasks update the UI?+

Through cx.dispatcher() — a cloneable typed sink. Move it into any future; dispatched actions land in update() on the UI thread. No locks, no channels in user code.

How does flexbox work on a cell grid?+

taffy computes continuous layout; quantize_rect rounds absolute edges once, clamps every child inside its parent, and forces a 1-cell minimum when taffy assigned a positive size. Text participates via a measure function, so wrapping is layout-aware.

What happens when my view panics?+

A panic hook restores raw mode, leaves the alt screen, and disables mouse capture before the default hook prints the backtrace. Proven on a real PTY for panics inside both view() and update().

How do I handle keyboard input?+

Implement handle_key on your view — it runs before any global routing. Return true to consume the event. q is reserved as the global quit key by VeloceApp::run.

Does it work on macOS and Windows?+

Linux x86_64 is verified here (build + PTY e2e). macOS and Windows via WSL/Windows Terminal use the same portable crossterm/ratatui paths but are not verified in this environment.

Is it on crates.io?+

Not yet — publishing needs the owner's token. File manifests are package-validated; releases will go leaf-crate first.

What is intentionally out of scope?+

Hot-reload/dev-server, mouse-wheel scrolling, non-terminal backends, and a memoized layout cache. The docs site keeps the full deferred list.
